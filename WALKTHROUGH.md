# Руководство администратора: Развертывание автономного CTF-сервера

В этом документе содержится детальная пошаговая инструкция по подготовке, конфигурированию и тестированию инфраструктуры для проведения оффлайн CTF соревнований.

---

## 1. Подготовка виртуальной машины сервера (Debian 13)

### Рекомендуемые параметры VirtualBox для сервера:
- **ОС:** Debian 13 (64-bit).
- **Процессор:** от 4 vCPU (зависит от числа участников и запускаемых контейнеров).
- **Оперативная память:** от 4 до 8 ГБ.
- **Диск:** 40+ ГБ (с запасом под кэш Docker-образов и инстансов).
- **Сетевой адаптер 1 (на этапе установки):** NAT (для первоначального выхода в интернет и скачивания пакетов и образов).
- **Сетевой адаптер 1 (на этапе соревнований):** «Внутренняя сеть» (Internal Network) с именем `ctf-net` (или «Сетевой мост» / Bridged Adapter при подключении участников через внешний коммутатор).

---

## 2. Развертывание платформы (этап с интернетом)

Все подготовительные действия выполняются на сервере Debian 13, пока у него есть доступ в интернет.

### Шаг 2.1. Клонирование репозитория
```bash
sudo su -
mkdir -p /opt/ctfd
cd /opt/ctfd
git clone https://github.com/starsden/ctfd .
```

### Шаг 2.2. Запуск базовой настройки
Скрипт `scripts/setup-host.sh` автоматически:
1. Установит необходимые пакеты (`docker-ce`, `docker-compose-plugin`, `dnsmasq`, `jq` и др.).
2. Назначит интерфейсу статический IP `192.168.100.1/24`.
3. Сконфигурирует легковесный DHCP и DNS сервер `dnsmasq`.
4. Инициализирует локальный Docker Swarm и назначит ноде метку `name=linux-1`.
5. Клонирует плагин `ctfd-whale`.
6. Настроит systemd-юнит `ctfd.service` для автозапуска при загрузке ОС.

```bash
chmod +x scripts/*.sh
./scripts/setup-host.sh
```

### Шаг 2.3. Кэширование всех Docker-образов
Запустите скрипт предзагрузки образов:
```bash
./scripts/prepull-images.sh
```
Этот скрипт:
- Скачивает базовые образы CTFd: `ctfd/ctfd:latest`, `mariadb:10.11`, `redis:7-alpine`.
- Скачивает популярные базовые образы для заданий: `php:8.2-apache`, `python:3.11-slim`, `ubuntu:22.04`, `alpine:3.19`.
- Собирает демонстрационное задание `ctf/web-sample:latest`.

## 3. Резервное сохранение образов (для переноса без интернета)

Если сервер настраивается на одной машине, а соревнование будет проводиться на изолированном ПК:
```bash
# На машине с интернетом:
./scripts/export-offline-bundle.sh
# Будет создан архив: ctfd-offline-bundle.tar.gz

# На изолированной машине:
./scripts/import-offline-bundle.sh ctfd-offline-bundle.tar.gz
```

## 4. Конфигурация плагина CTFd-Whale

Плагин **CTFd-Whale** отвечает за создание изолированных Docker-контейнеров под каждого участника/команду.

### Шаг 4.1. Первый вход в CTFd
1. Запустите сервис:
   ```bash
   systemctl start ctfd.service
   ```
2. Откройте в браузере `http://192.168.100.1` (или `http://ctf.local`).
3. Заполните мастер начальной настройки CTFd:
   - Название CTF (например, `Local Offline CTF 2026`).
   - Логин и пароль главного администратора.
   - Режим соревнования (User Mode или Team Mode).

### Шаг 4.2. Настройка плагина Whale
1. В верхнем меню перейдите в **Admin Panel** -> вкладка **Whale** (или значок шестеренки/кита).
2. Настройте параметры:
   - **Docker Node**: `linux-1` (соответствует метке ноды Swarm, заданной в `setup-host.sh`).
   - **Auto Connect Network**: включить (или указать `bridge`).
   - **Docker Host**: оставить пустым или `unix:///var/run/docker.sock`.
   - **Port Range**: `20000-20500` (диапазон динамических портов заданий).
   - **Routing Mode**: выбрать **Direct** (прямой проброс портов на хост, исключает необходимость внешнего frp прокси в оффлайн сети).
   - **Challenge Timeout**: `1800` (время жизни инстанса в секундах, 30 минут).
   - **Container Max Count**: `1` (максимальное число одновременно запущенных контейнеров на одного участника).
3. Нажмите **Update** для сохранения настроек.

## 5. Создание динамического задания в CTFd

Для добавления нового задания на базе Docker:

### Шаг 5.1. Сборка локального образа
Каждое задание должно быть заранее собрано и иметь локальный тег.
Пример сборки тестового задания:
```bash
cd /opt/ctfd/challenges/web-sample
docker build -t ctf/web-sample:latest .
```

### Шаг 5.2. Добавление задания через веб-интерфейс
1. В Admin Panel перейдите в **Challenges** -> **+** (New Challenge).
2. В выпадающем списке типов выберите **`dynamic_docker`**.
3. Заполните поля:
   - **Name**: `Warmup Web Challenge`.
   - **Category**: `Web`.
   - **Message / Description**:
     ```markdown
     Добро пожаловать на соревнование!
     Запустите ваш персональный контейнер с заданием.
     
     Сервис доступен по адресу:
     `http://ctf.local:{port}`
     ```
   - **Initial / Minimum / Decay**: баллы за задание (например, 500, 100, 15).
   - **Docker Image**: `ctf/web-sample:latest` *(строго локальное имя!)*.
   - **Frp Redirect Type**: `Direct`.
   - **Redirect Port**: `80` *(внутренний порт, который слушает приложение в контейнере)*.
   - **Dynamic Flag**: включить (флаг автоматически генерируется и передается в переменную окружения `FLAG`).
4. Нажмите **Create**.
5. Задание готово! В карточке появится кнопка «Запустить инстанс» (Launch Instance).

## 6. Перевод в оффлайн-режим (День соревнований)

1. **Изоляция сети в VirtualBox:**
   - Выключите VM сервера Debian 13.
   - В настройках VirtualBox переключите Сетевой Адаптер 1:
     - Тип подключения: **Внутренняя сеть (Internal Network)**.
     - Имя сети: `ctf-net`.
     - Неразборчивый режим: **Разрешить всё**.
   - Включите VM сервера Debian 13.

2. **Проверка готовности:**
   Выполните скрипт комплексной диагностики:
   ```bash
   /opt/ctfd/scripts/verify-offline.sh
   ```
   Скрипт проверяет:
   - Наличие адреса `192.168.100.1`.
   - Активность `dnsmasq` на портах 53 (DNS) и 67 (DHCP).
   - Резолвинг домена `ctf.local`.
   - Статус Docker Swarm и ноды `linux-1`.
   - Наличие всех образов в кэше.
   - Запуск контейнеров CTFd, MariaDB, Redis.
   - Доступность веб-интерфейса.
   - Успешный запуск контейнера задания без обращения к внешней сети.

## 7. Инструкция для участников (Kali Linux)

1. **Настройка ВМ участника в VirtualBox:**
   - Настройки -> Сеть -> Адаптер 1.
   - Тип подключения: **Внутренняя сеть (Internal Network)**.
   - Имя сети: `ctf-net`.
   - Неразборчивый режим: **Разрешить виртуальным машинам** или **Разрешить всё**.

2. **Запуск и подключение:**
   - Запустить Kali Linux.
   - Сетевой менеджер автоматически получит адрес через DHCP:
     - IP адрес: `192.168.100.X` (в диапазоне от .50 до .200).
     - Маска: `255.255.255.0`.
     - DNS: `192.168.100.1`.
   - Проверить соединение в терминале Kali:
     ```bash
     ping -c 2 ctf.local
     ```
   - Открыть браузер Firefox в Kali Linux и перейти по адресу:
     **`http://ctf.local`** (или `http://192.168.100.1`).
   - Зарегистрироваться и приступать к решению заданий!

## 8. Мониторинг и обслуживание во время игры

Администратор сервера может в реальном времени отслеживать происходящее:

- **Просмотр выданных IP адресов участникам:**
  ```bash
  cat /var/lib/misc/dnsmasq.leases
  # или лог подключений:
  tail -f /var/log/dnsmasq.log
  ```

- **Просмотр запущенных контейнеров заданий:**
  ```bash
  docker ps
  ```

- **Просмотр логов CTFd:**
  ```bash
  docker compose -f /opt/ctfd/docker-compose.yml logs -f ctfd
  ```

- **Принудительная очистка зависших инстансов заданий:**
  ```bash
  # Плагин Whale удаляет их по истечении таймера, но если нужно очистить вручную:
  docker rm -f $(docker ps -q --filter "label=whale")
  ```

## 9. Автозапуск и отказоустойчивость

Все компоненты настроены на автоматический запуск при старте ОС:
- `dnsmasq.service` — включен через `systemctl enable dnsmasq`.
- `docker.service` — включен через `systemctl enable docker`.
- `ctfd.service` — запускает контейнеры CTFd через `docker compose up -d` после готовности Docker.
- При случайной перезагрузке виртуальной машины или сбое питания сервер полностью восстанавливает работу без участия оператора.
